# WaveShare 使用者故事與驗收條件

每則說明「誰想做什麼、為什麼」，以及怎麼驗收。**現況**是編寫時的主分支；[PR #1](https://github.com/ChristingChang/waveshare/pull/1) 和 [PR #2](https://github.com/ChristingChang/waveshare/pull/2) 尚未合併。核取方塊是驗收項目，不是通過紀錄。[回文件首頁](README.md)

## 登入與帳號

### US-01｜登入我的日誌（現況）

身為浪友，我想用自己的帳號登入，方便回到個人日誌。

- [ ] 未登入時開啟日誌頁，被導往 Manus 登入，且不顯示紀錄內容。
- [ ] 授權成功後回到首頁；用同一個 Manus 帳號再次登入，仍能看到原有紀錄。

### US-04｜改用 Google 登入（PR #2）

身為浪友，我想用熟悉的 Google 帳號登入，不用另外開 Manus 或 GitHub 帳號。

- [ ] 未登入時開啟 WaveShare，會自動前往 Google 登入與授權；成功後回到首頁。
- [ ] 取消授權或收到無效的登入回應時，不會登入 WaveShare。
- [ ] 用同一個 Google 帳號再次登入，仍能看到自己的紀錄。
- [ ] 舊 Manus 使用者第一次用 Google 登入時，即使電子郵件相同，也不會自動取得舊日誌或好友。

### US-05｜資料存在 TiDB Cloud（PR #2）

身為網站維護者，我想確認 TiDB Cloud 能保存日誌資料，好讓換資料庫後仍能記錄衝浪。

- [ ] 在已建立資料表的測試環境，完成 Google 登入，新增一筆帶影片的紀錄，再重新登入確認紀錄仍能開啟。
- [ ] 修改心得後重新整理，仍能讀到新內容。
- [ ] 若另外安排搬遷舊資料，須核對筆數、擁有者、好友關聯及舊影片能否播放；PR #2 本身不會搬資料。

## 記錄與回顧

### US-10｜新增一筆衝浪紀錄（現況／PR #1）

身為浪友，我想上傳影片並記下當天的浪況，好在日後回顧。

- [ ] 選一段短 MP4、日期、浪點與 1 至 5 顆星的評分；浪板與心得留空仍可儲存。儲存後可在相應日期的日曆找到該筆紀錄。
- [ ] 沒選影片或浪點時不能完成儲存；影片傳輸失敗也不會建立紀錄。

### US-11｜不必把影片壓到很小（PR #1）

身為浪友，我想直接上傳普通的手機影片，不必先把它壓到 Vercel 的請求上限以下。

- [ ] 在已設定 R2 的測試站，上傳一支 50 MB、瀏覽器可播放的 MP4，儲存後能從詳細頁播放。
- [ ] 空檔、不支援的格式或超過 100 MiB 的影片不能開始上傳。若在上傳網址到期後才開始傳輸，不能用該網址完成儲存。

### US-12｜限制上傳申請（PR #1）

身為網站維護者，我想限制每個帳號的上傳申請次數，以減少濫用。

- [ ] 同一帳號在任意連續 24 小時內可以申請 10 次；放棄上傳也會計入。
- [ ] 第 11 次申請被擋下並提示已達上限；另一個帳號的次數不受影響。

### US-14｜更正已存的日誌（現況）

身為浪友，我想更正記錯的浪點或評分，不必重新上傳影片。

- [ ] 從自己的紀錄開啟編輯，改浪點和評分後儲存；詳細頁顯示新資料。
- [ ] 現有影片仍相同；編輯畫面沒有更換影片的功能。

### US-15｜刪除不想保留的紀錄（現況／PR #1）

身為浪友，我想移除一筆紀錄，讓它不再出現在自己的日誌。

- [ ] 按取消時資料不變；確認刪除後，該日誌不再出現在日曆或統計。
- [ ] 現況：影片檔不隨日誌刪除。PR #1：最後一筆使用某 R2 影片的日誌被刪除時，系統會嘗試刪除影片；若還有其他日誌用到它，必須保留。

### US-17｜清理沒存成紀錄的影片（PR #1，選用）

身為網站維護者，我想清理沒有日誌引用的舊上傳，避免多付儲存費。

- [ ] 啟用每日清理後，申請超過 24 小時且未被引用的 R2 上傳會被處理；仍有引用、未到時限和舊 Forge 影片都保留。
- [ ] 未啟用或請求未授權時不清理；刪檔出錯時保留上傳申請，供下次重試。

### US-20｜按日期、浪點或浪板回顧（現況）

身為浪友，我想用日曆、地圖及統計回顧，方便找到某趟衝浪或比較自己的習慣。

- [ ] 在不同日期新增兩筆同浪點的紀錄，切換月份後可以找到各自的日期和詳細頁。
- [ ] 地圖顯示該浪點已造訪兩次，統計頁反映兩筆紀錄及有填寫的浪板類型；別人的紀錄不計入。

## 好友與隱私

### US-31｜加常一起衝浪的人為好友（現況）

身為浪友，我想搜尋並邀請認識的浪友，方便在好友列表找到對方。

- [ ] A 用姓名或 Email 找到 B，送出邀請後，只有 B 的待處理清單顯示這筆邀請。
- [ ] 接受後雙方都出現在彼此的好友清單。拒絕時不成為好友，且現況不允許再送同一組的邀請。

### US-40｜只有我能管理我的日誌（現況）

身為紀錄擁有者，我希望別人不能查看、修改或刪除我的日誌。

- [ ] 用兩個已成為好友的測試帳號確認：B 打開 A 的日誌頁網址，仍看不到該筆紀錄。
- [ ] 若 B 嘗試修改或刪除 A 的紀錄，A 的資料保持原樣，不以畫面是否報錯判斷。

### US-43｜知道影片網址的可見範圍（PR #1）

身為浪友，我想知道影片會不會被其他人看到，方便決定要不要上傳。

- [ ] 未登入的人打不開別人的日誌頁；但在未登入的視窗直接開啟同一支影片的公開 R2 網址，若檔案存在且格式相容，仍可播放。
- [ ] 驗收時分開測試「日誌網址」、「上傳網址」與「播放網址」；不把上傳網址的有效期限當成播放期限。

### US-51｜指定誰能看我分享的日誌（草案，未實作）

身為浪友，我想選擇哪些好友可以看某筆紀錄，而不是讓所有知道網址的人都能看。

- [ ] 提案：新紀錄預設不分享，只有經紀錄擁有者同意的對象可以查看。
- [ ] 提案：取消分享後，對方既看不到日誌，也不能用先前取得的影片網址播放。這需要先改用私人播放方式。
